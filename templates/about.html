About the Rule-Based Expert System

A comprehensive reference on the architecture, knowledge representation, forward-chaining inference, and college viva examination concepts implemented in this project.

What is an Expert System?

An Expert System is a branch of Artificial Intelligence designed to emulate the decision-making capability of a human specialist in a specific domain using formal knowledge rules and logical inference.

What is a Knowledge Base?

The Knowledge Base stores domain facts, career requirements, and heuristic logic. In this project, it is located in rules.py and comprises 84 structured production rules.

What are IF–THEN Rules?

IF–THEN rules (production rules) connect antecedents to consequents: IF condition THEN conclusion. Each rule carries points (+10 strong, +5 medium, +2 basic).

What is Forward Chaining?

Forward Chaining is a data-driven reasoning strategy. It begins with known facts (student inputs in Working Memory) and searches the Knowledge Base for rules whose IF conditions match, firing them to reach recommendations.

What is an Inference Engine?

The Inference Engine executes the reasoning cycle. Implemented in inference_engine.py, it pattern-matches user facts, fires matching rules, resolves conflicts, normalizes scores, and returns the top 3 careers.

Rule-Based Expert System vs Machine Learning

Key technical differences for college viva presentations:

Dimension Rule-Based Expert System (This Project) Machine Learning / Neural Networks
Knowledge Source Explicit human-crafted IF–THEN rules Learned statistical patterns from large datasets
Explainability 100% Explainable (Fired rules logged) Black box (Complex mathematical weights)
Data Requirement Zero training datasets needed Requires thousands of labeled training samples
Determinism Deterministic (Same input → same output) Probabilistic (Subject to statistical variance)
Knowledge Updates Add or edit a rule in rules.py Requires dataset collection and model retraining

College Mini Project Viva Questions & Answers

Q1: Why was forward chaining chosen over backward chaining?
Answer: Forward chaining is data-driven. We start with known student data (interests, skills, preferences) and reason forward to discover suitable careers. Backward chaining is goal-driven, which is suitable when testing a specific single hypothesis.
Q2: How are career scores and percentages calculated?
Answer: Each matching rule contributes confidence points: Strong (+10), Medium (+5), or Basic (+2). The percentage is computed as: (Score Obtained / Maximum Possible Score) * 100. Careers are ranked descending by score.
Q3: Where in the codebase is the Knowledge Base and Inference Engine?
Answer: The Knowledge Base is defined in rules.py (containing KNOWLEDGE_BASE_RULES and CAREER_METADATA). The Inference Engine is implemented in inference_engine.py in the InferenceEngine class.
